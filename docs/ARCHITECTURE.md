# How the source is organised

The whole engine is one file, `src/kestrel_3_0.cpp` (about 11,000 lines, 4,684 of them Fathom), plus the 76 MB network that the assembler pulls in with `.incbin "kestrel_net.bin"`. The line numbers below are for 3.0 and only approximate; they are meant as a map, not as a reference.

| Lines | What is there |
|---|---|
| 1 - 63 | includes, platform switches (Windows / Linux / macOS), `KThread`: a `std::thread` replacement with an 8 MB stack (the default stack of musl and macOS threads is too small for a deep search) |
| 65 - 183 | bit tricks, Zobrist keys and attack tables (`initTables`), sliding-piece attacks; with BMI2 the attacks come from PEXT tables (`initPext`), but only on CPUs where PEXT is fast (Intel, AMD Zen 3 and newer), otherwise from the classic tables |
| 185 - 398 | **the network**: the embedded weights and the platform-specific assembler section names, `initNet` / `nnLoadFile` (the `EvalFile` option), `netEval` with an AVX2 path (pairwise product of the two accumulators, a second layer that skips the zero inputs and sums in float32 (an int32 sum could overflow before 2.3), a float tail with FMA) and a plain C++ path with exactly the same results, `featIdx` / `nnBase` (24,576 inputs per side, 32 mirrored king buckets) |
| 400 - 767 | `Pos`: the board, `make` / `unmake`, move generation, legality, repetition and fifty-move draws, hash keys, and the **accumulators** of the network: they are updated lazily (only for positions that are really evaluated) and king moves use a refresh cache |
| 769 - 786 | move printing and `perft` |
| 787 - 953 | the old hand-written evaluation of 1.x. It is no longer used in normal play; it stays for `UseNNUE false` and for tests |
| 954 - 5637 | **Fathom** (new in 3.0), the Syzygy tablebase reader by Ronald de Man, basil00 and Jon Dart (MIT licence; the notice is at the top of the block and in `THIRD_PARTY_NOTICES.txt`). It is the only part of the file that Claude did not write: its source files are pasted in one after the other, inside `namespace fathom`, with the compiler warnings it causes switched off by pragmas. The engine calls `tb_init`, `tb_probe_wdl` and `tb_probe_root_dtz` |
| 5639 - 5701 | the engine side of Syzygy: the options (`SyzygyPath`, `SyzygyProbeDepth`, `Syzygy50MoveRule`, `SyzygyProbeLimit`), `tbProbeWdl`, `tbSetPath`, and `tbRootBans`, which turns the DTZ / WDL ranking of the root moves into the list of moves that are not searched |
| 5702 - 5807 | state shared by all threads: the transposition table (4-entry buckets of two atomic 64-bit words, aged by generation), time limits, `hashMB`, the option variables |
| 5808 - 10311 | **the search, eight times**: namespaces `S0` ... `S7`, one per search thread, each a complete copy (own position, history tables, move stacks, killers, correction history). Inside one copy: `evaluate`, SEE (`seeGE`), move ordering (`moveScore`, `quietScore`), `qsearch`, `search` (principal-variation search with null move, reverse futility, ProbCut, internal iterative reduction, late-move reductions and pruning, futility and SEE pruning, singular extensions, tablebase probes at interior nodes), `helperMain` (the iterative deepening of a helper thread, with its own pattern of skipped depths). The copies are identical text; one namespace per thread keeps the thread-private tables out of any shared structure. |
| 10312 - 10328 | glue for the copies (`using namespace S0` for the main thread), node counters (`totalNodes`), and `winFullSpeed`, which asks Windows not to put the engine in "efficiency mode" (EcoQoS) |
| 10329 - 10505 | the experience (position learning) file and the opening book |
| 10506 - 10537 | `go perft` |
| 10538 - 10701 | `think`: the iterative deepening of the main thread, aspiration windows, time management (soft limit checked after each iteration, hard limit inside the search), MultiPV, book, experience and tablebase lookups at the root, the `info` and `bestmove` output |
| 10702 - 10732 | `accWalk`: the accumulator self-test (every position of a game tree against a rebuild from scratch) |
| 10733 - end | `main`: start-up (tables, network, hash), the command-line modes (`bench`, `acctest`, `perft`, ...), then the UCI command loop with the option parsing |

## Things worth knowing

* **Why eight copies of the search?** Each thread works on static data of its own namespace, so nothing is shared except the transposition table and the stop flag. The price is the size of the file; the copies are identical and are generated by a patch chain that is not part of this repository.
* **Determinism:** with one thread the search is deterministic. The depth-12 `bench` (`kestrel bench 12`) gives the same node count on every platform and for the plain and the AVX2 code (859,322 for 3.0; the number is recorded in `tests/BENCH` and checked by the GitHub Actions workflow). If you change anything in the search or the evaluation, the number changes; if you only change speed, it must not.
* **The network is not in git** (76 MB per version). It is a release asset (`kestrel_net_3_0.bin`), must be saved as `kestrel_net.bin` in the directory where the compiler runs, and can be replaced at run time with `EvalFile`.
* **Syzygy files are not in git either.** With no `SyzygyPath` the engine never touches the tablebase code; see [SYZYGY.md](SYZYGY.md).
* **Search constants** such as the pruning margins sit directly in `search`; in the development builds of 2.2 they are options (`T_...`) for tuning.
