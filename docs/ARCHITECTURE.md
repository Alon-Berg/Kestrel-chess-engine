# How the source is organised

The whole engine is one file, `src/kestrel_2_0.cpp` (about 5,900 lines), plus the 76 MB network that the assembler pulls in with `.incbin "kestrel_net.bin"`. The line numbers below are for 2.1 and only approximate; they are meant as a map, not as a reference.

| Lines | What is there |
|---|---|
| 1 - 63 | includes, platform switches (Windows / Linux / macOS), `KThread`: a `std::thread` replacement with an 8 MB stack (the default stack of musl and macOS threads is too small for a deep search) |
| 65 - 183 | bit tricks, Zobrist keys and attack tables (`initTables`), sliding-piece attacks; with BMI2 the attacks come from PEXT tables (`initPext`), but only on CPUs where PEXT is fast (Intel, AMD Zen 3 and newer), otherwise from the classic tables |
| 185 - 372 | **the network**: the embedded weights and the platform-specific assembler section names, `initNet` / `nnLoadFile` (the `EvalFile` option), `netEval` with an AVX2 path (pairwise product of the two accumulators, a second layer that skips the zero inputs and sums in float32 (an int32 sum could overflow before 2.3), a float tail with FMA) and a plain C++ path with exactly the same results, `featIdx` / `nnBase` (24,576 inputs per side, 32 mirrored king buckets) |
| 385 - 755 | `Pos`: the board, `make` / `unmake`, move generation, legality, repetition and fifty-move draws, hash keys, and the **accumulators** of the network: they are updated lazily (only for positions that are really evaluated) and king moves use a refresh cache |
| 756 - 773 | move printing and `perft` |
| 774 - 940 | the old hand-written evaluation of 1.x. It is no longer used in normal play; it stays for `UseNNUE false` and for tests |
| 941 - 1034 | state shared by all threads: the transposition table (4-entry buckets of two atomic 64-bit words, aged by generation), time limits, `hashMB`, the option variables |
| 1035 - 5242 | **the search, eight times**: namespaces `S0` ... `S7`, one per search thread, each a complete copy (own position, history tables, move stacks, killers, correction history). Inside one copy: `evaluate`, SEE (`seeGE`), move ordering (`moveScore`, `quietScore`), `qsearch`, `search` (principal-variation search with null move, reverse futility, ProbCut, internal iterative reduction, late-move reductions and pruning, futility and SEE pruning, singular extensions), `helperMain` (the iterative deepening of a helper thread). The copies are identical text; one namespace per thread keeps the thread-private tables out of any shared structure. |
| 5243 - 5420 | glue for the copies (`using namespace S0` for the main thread), node counters, the experience (position learning) file, the opening book |
| 5458 - 5600 | `think`: the iterative deepening of the main thread, aspiration windows, time management (soft limit checked after each iteration, hard limit inside the search), MultiPV, book and experience lookups, the `info` and `bestmove` output |
| 5600 - 5630 | `accWalk`: the accumulator self-test (every position of a game tree against a rebuild from scratch) |
| 5630 - end | `main`: start-up (tables, network, hash), the command-line modes (`bench`, `acctest`, `perft`, ...), then the UCI command loop with the option parsing |

## Things worth knowing

* **Why eight copies of the search?** Each thread works on static data of its own namespace, so nothing is shared except the transposition table and the stop flag. The price is the size of the file; the copies are identical and are generated by a patch chain that is not part of this repository.
* **Determinism:** with one thread the search is deterministic. The depth-12 `bench` (`kestrel bench 12`) gives the same node count on every platform and for the plain and the AVX2 code (1,051,844 for 2.1; the number is recorded in `tests/BENCH` and checked by the GitHub Actions workflow). If you change anything in the search or the evaluation, the number changes; if you only change speed, it must not.
* **The network is not in git** (76 MB per version). It is a release asset (`kestrel_net_2_0.bin`), must be saved as `kestrel_net.bin` in the directory where the compiler runs, and can be replaced at run time with `EvalFile`.
* **Search constants** such as the pruning margins sit directly in `search`; in the development builds of 2.2 they are options (`T_...`) for tuning.
