# Tests

Black-box tests: every script takes the path of a Kestrel executable and talks to it over UCI. They need Python 3 and `pip install chess` (python-chess is the rules oracle in some of them). The scripts print their result on the last line(s); they exit with 0 even when something failed, so look at the output (the GitHub Actions workflow in `.github/workflows/verify-release.yml` greps for the pass lines).

| Script | What it checks |
|---|---|
| `audit_probe.py <exe>` | 83 protocol and robustness cases: CRLF, garbage input, no legal move, clock handling, mate at the fifty-move boundary, ... |
| `audit_sem.py <exe>` | 31 rule and protocol checks against python-chess (castling, en passant, promotion, repetition, ...). Since 3.0 the check "promotion to queen when winning" also accepts a quiet winning move whose principal variation promotes within the next two moves (the 3.0 network sometimes plays Ka2 before a8=Q in `8/P6k/8/8/8/8/8/K7`; both win) |
| `edge_test.py <exe> [timeout]` | 303 edge cases of the UCI protocol; the process must stay alive, answer `isready` and give a legal `bestmove` for every `go` |
| `chess960_test.py <exe> [games] [seed]` | Chess960: legal moves against python-chess from random start positions, castling notation, short games |
| `clock_limit_test.py <exe>` | a clock next to a depth or node limit must be obeyed (all limits of a `go` apply at once) |
| `test_uci_features.py <exe>` | MultiPV, ponder, Clear Hash, UCI_LimitStrength, threads |
| `interop_test.py <exe>` | the engine driven by python-chess's own UCI client (ponder hits and misses, Chess960, new games) |
| `options_test.py <exe>` | sends the declared default of every option (what a "reset to defaults" does) and requires the search to be identical to one with no option sent; Kestrel 2.0 and 2.1 fail it (they declared `NNBlend` with default 70 but ran at 100) |
| `tb_test.py <exe> <syzygy folder> [positions] [seed] [conversion games]` | Kestrel 3.0 and later: Syzygy probing against python-chess reading the same files (win/draw/loss of random 3-5 man positions, the root move filter, search, and conversion of won endgames to a mate). `TB_MAXMEN=4` limits it to 3 and 4 men, `TB_THREADS=n` sets `Threads`; the last line is `tb_test: PASS` or `FAIL`. Needs the tablebase files (see `docs/SYZYGY.md`) |
| `breakers.py <exe> [--quick] [--only sections] [--seed N] [--timeout S] [--threads N] [--syzygy FOLDER] [--list]` | positions that break engines (Kestrel 3.0 and later; needs `go perft`): the move generator on 37 hard positions (en passant that exposes the king, castling through attacked squares, promotions with check, 218 legal moves, Chess960 castling) against the counts of python-chess; mate in one that only an underpromotion, a castling, an en passant capture or a double check delivers; stalemate traps and won positions where a stalemating move must not be played; one legal move, no legal move, MultiPV larger than the number of moves; a game of 3,880 plies, halfmove clocks and move numbers up to 2^64, odd castling flags; many-queen positions that drive the search to its maximum ply; 300 random legal positions (perft 1 to 3 and a legal move); 214 endings of 3 to 5 men that fool an engine without tablebases (section `eval`; the truth was read from the Syzygy 3-4-5 files): 125 breakers (positions where 3.0 throws a win away or loses a draw at 50,000 and at 200,000 nodes; mostly queen against two bishops or two knights, two bishops against a knight, queen and pawn against queen; 60 of them even at 1,000,000 nodes), 42 controls (hard positions it plays right, among them Reti's study and Fine's position 70: a failure is a problem) and 47 positions where the move is right but the score is far from the truth (a draw shown as +3.5 or more, a win as +0.7 or less); the breakers and those scores are weak spots, not problems (`--list` prints the ones that still beat the engine), and with `--syzygy` all 214 must be played right (3.0 does: the tablebases fix every breaker); with `--syzygy` also 400 endings with en passant, castling rights and fifty-move counters against python-chess reading the same files. Run it on an AddressSanitizer / UBSan build too: the process must not exit, print on stderr or answer with an illegal move. With `--threads` above 1, Kestrel 3.0 fails the stalemate-trap checks that use `go nodes` (the first helper thread that reached the node limit ended the search before the main thread had searched anything; fixed in 3.1). Known behaviour of 3.0 and 3.1: the moves of a `position ... moves` list beyond ply 3,900 are ignored (reported as a NOTE); with tablebases a mate in one whose position is in the tables scores as a tablebase win (about 28000, below every mate score), so the engine can play a mate in two instead (the mate section then accepts any move that keeps a forced win); a halfmove clock of 2,147,483,647 or more in a FEN is signed overflow, harmless in the normal build but fatal in a UBSan build (still there in 3.1; so is a FEN rank that does not add up to eight files, a shift by a negative number in `setFen`, which `edge_test.py` finds under UBSan). Last line: `breakers: PASS` or `breakers: FAIL (n problems)`; `--quick` takes about 15 s (293 checks), the full run about 90 s (807 checks, the section `eval` is about 50 s of them; measured on a quiet PC with the packaged x86-64-v3 build) |
| `uci_fuzz.py <exe> <sequences> <seed>` | random command sequences; the engine must survive and answer |
| `race_test.py <exe> <runs>`, `infinite_test.py <exe>` | `go infinite` followed by an immediate `stop` (sent after `readyok`, so that a slow start of the 80 MB program on a busy machine is not counted as a hang; Kestrel 3.0 and later); `go infinite` must wait for `stop` |
| `stress_stop.py <exe> <iterations> <seed> <threads>` | random go / stop / position / ucinewgame / setoption bursts with millisecond gaps; `threads` can be up to 128 for Kestrel 3.1 (more threads than processors is fine for this test) |
| `longlist_test.py <exe>` | a move list of 4,000 plies |
| `depth1_test.py <exe> [threads=128] [trials=40] [movetime=60]` | Kestrel 3.1 and later: short searches with many threads must still search. `go movetime 60` with 128 threads in three positions (one of them a stalemate trap): every search must print at least one `info depth` line and the engine must not play the stalemating move. Kestrel 3.0 and the first 3.1 candidate fail it on a computer with fewer processors than threads or a busy one (39 of 60 searches ended before depth 1 with 128 threads on a busy 22-processor laptop, because the helper threads took longer to start than the hard limit and the first time check of a thread runs at node 0); since 3.1 a time limit cannot end a search before depth 1 has completed. Last line: `depth1_test: PASS` or `depth1_test: FAIL (...)` |
| `BENCH` | the depth-12 bench node count of the source in `src/` (`kestrel bench 12`) |

Tests of the play page (`docs/play`, WebAssembly build); they need Deno (https://deno.com) and, for the first one, `pip install chess`:

| Script | What it checks |
|---|---|
| `web/gen_rules_cases.py [games] [seed]`, then `deno run --allow-read web/rules_test.js` | the rules code of the page (`docs/play/rules.js`) against python-chess: legal moves, SAN, the position after every move, check / checkmate / stalemate / insufficient material / fifty-move flags on about 29,000 positions of random games (and the six standard perft positions) |
| `deno run --allow-read web/wasm_bench_test.js <kestrel_net.bin>` | `kestrel.wasm` and `kestrel-nosimd.wasm` give the native results: bench 12 = 859,322 nodes, the start position to depth 12 = 63,397 nodes, `go infinite` refused |
| `deno run web/levels_test.js` | the levels of the page (`docs/play/levels.js`) without an engine: the table is ordered (ratings up, depth up, carelessness down), the engine's lines are read correctly, moves are chosen with the stated weights, a won position makes a level steadier, the commands sent to the engine |
| `deno run --allow-read web/levels_engine_test.js <kestrel_net.bin>` | every level with the real WebAssembly engine: a legal move in five positions, inside its depth limit, the same move for the same random numbers, a mate in one found from Level 7 up in at least 19 of 20 tries, weaker levels agree less often with the best move (about 3 minutes) |

The long test suite that also builds the engine with AddressSanitizer / UBSan, and the scripts that need local data files, are not part of this repository; their logs are in `logs/`.
